# Activity Log (`/activity`)

## What It Does
Chronological system event log. Filter by type: all / alert / system / detection / performance. Pipeline step visualization (Ingest → Features → Anomaly → Classifier → Alert → Export). Severity-coded entries. Expandable entries showing full payload and decision path. Timestamp for each entry.

## Data Flow
- Log entries generated by `generateMockLogs(count)` in `ActivityPage.tsx`
- Template strings with random IP substitution: `"SYN flood detected — 12K pkt/s from {ip}"`
- Pipeline step stats computed from mock data
- Also receives live alerts via WebSocket `useWebSocketContext`
- No dedicated backend API endpoint for activity log

## What Is Real
- Live alert entries that come through WebSocket from the backend detection engine
- Timestamps of WebSocket-delivered alerts are real

## What Is Fake
| Data | How |
|------|-----|
| Log entries (initial) | `generateMockLogs(50)` — picks from 20 message templates, substitutes random IPs |
| Message templates | 20 hardcoded strings covering all threat types |
| Severity assignment | Weighted random per entry |
| Pipeline step throughput | Random values: "~10K flows/s", "~9.8K flows/s", etc. |
| Decision path strings | Randomly assembled from pipeline step names |
| Full payload | Random JSON-like strings |
| Performance metrics | Random latency and throughput numbers |

## Verdict
**~30% real.** The 20 message templates cover real threat scenarios, but all entries are generated locally. The only real data comes from WebSocket alerts that occasionally appear in the feed.
